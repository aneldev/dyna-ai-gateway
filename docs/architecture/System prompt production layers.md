# AI Gateway — System prompt layers

Status: 2026-10-30. Source: `src/internal/prompt-template-store/utils/seedTemplates.ts` (the template), `src/internal/context-assembler/ContextAssembler.ts` (the slots).

Every `ask()` / `run()` sends one system prompt. It is the `CHAT_MAIN` template with its slots filled. The template is one text; the slots are the layers, from the most general to the most specific. A developer who asks "where does this sentence in the prompt come from, and where do I put mine?" finds the answer in this table.

Between layers 4 and 5 the template holds `{cacheBreakpoint}`. It renders to nothing; it marks where the part that is the
same on every call of a profile ends. With `contextAssembler.promptCaching: true` the prompt is sent as two blocks split
there: the stable block (layers 1–4, marked for the provider's prompt cache) and the per-call block (layers 5–9). A call
that passes its own `skills` changes the stable block: calls with the same skill set share one cache entry, a different
set writes another. With
`sharePromptCacheAcrossTenants: false` the stable block opens with one extra line, `[cache scope <hash>]`, a hash of the
tenant id, so tenants never share a cache entry. See the FAQ, "Is the system prompt cached, and what does it cost?".

The user's prompt itself (`IGatewayAskInput.prompt`) and the thread's turns are **not** in the system prompt: they are the messages. Which turns, and how many, is the working memory's decision, made with the tokens the rendered system prompt leaves ([D122](Decisions.md#d122-the-working-memory-owns-the-threads-window)).

## Which layer to use

- **Rule for the whole tenant or product** ("you are the assistant of Nordwind", tone, forbidden topics) → `promptAddendum` on the profile, stored once. Different behaviours → different profiles, chosen per call with `profileId`.
- **Long rules that few calls need** (the refund policy, an escalation procedure, an export format) → `skills` on the profile, or on the call. A `run()` reads only the names and descriptions and loads a body when a task needs it; an `ask()` gets the bodies whole ([D124](Decisions.md#d124-skills-instructions-the-model-loads-on-demand)).
- **Rule for this one call** ("one sentence", "offer the premium plan first", "the user is an admin") → `instructions`. Not stored; pass it on every call that needs it.
- **What the user is looking at** (the open invoice, the selected rows, the current page) → `context`. It is labelled as data because an app often builds it from user-typed values; the model must not take a "ignore your rules" inside it as a rule.
- **What should be true across calls** (the user's name, their timezone) → memory, written by the model or by `upsertUserFact`; not the prompt.
- **Documents** → the knowledge base, never pasted into `instructions` or `context`.

## Why this order

Stable before per-call, then general before specific. The first four layers are the same for every call of a profile (the template, the addendum, the skills, and the output format: one of a few fixed texts, the same for an app's calls in practice); everything from the date line on changes per call. A provider's prompt cache matches an exact prefix, so the stable layers come first, and the date line — the only per-call layer that used to sit at the top — follows the addendum. From there the model reads the call's rules, then the data of the call, then the long-lived notes, then the documents. A later layer can refine an earlier one ("be short" in the addendum, "but this time give all five steps" in the instructions). Data layers come last and carry a label that says they are data; the labels are a wording, not a barrier — the real protection against injected text is in the tools and approvals (see the FAQ, "How do I protect against prompt injection?").

## Changing the template

A stored `CHAT_MAIN` is cached only when it keeps `{cacheBreakpoint}` with nothing per-call before it: `{format}`,
`{addendum}` and `{skills}` may precede it, `{today}`, `{locale}`, `{timezone}`, `{instructions}`, `{context}`, `{memory}`
and `{kb}` may not. A per-call slot before it switches the cache off for the call, with the WARNING issue `prompt_cache_off`
naming the slot; a template without the placeholder is sent as one block, with no issue. A template without `{skills}`
drops the skills of a call that has some, with the WARNING issue `skills_slot_missing` naming the template version.

A tenant template (`PromptTemplateStore`, a new version of `CHAT_MAIN`) may drop a slot it does not want; a slot it keeps is filled as above. A slot named in the template and not in this list is a 400 at render time (`5372567786106`). `IAIProfile.templateOverrides` is declared and not yet read (see the [Roadmap](../Roadmap.md#planned)).
